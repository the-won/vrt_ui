레이어팝업 검증 하네스

페이지 안에 이미 존재하는 [data-pop] 영역을 숨겼다 보이게 하는 방식입니다. 파일을 가져오지 않습니다. 동작은 data-pop* 속성이, 생김새는 .lp-* 클래스가 담당합니다. 아래 10개 항목을 순서대로 눌러보며 확인하세요.

01

기본 열기 · 닫기

확인: 열고 닫을 때 확대·페이드 애니메이션이 실제로 보이는지. 툭 나타나면 강제 리플로우 처리가 빠진 것입니다. 닫기는 ① 닫기 버튼 ② X ③ 딤 클릭 ④ Esc 네 가지가 모두 동작해야 합니다.

02

딤 3종: true / false / static

확인: true는 딤이 보이고 딤 클릭 시 닫힘. false는 딤이 아예 생성되지 않고 뒤 페이지의 버튼이 그대로 클릭됨(투명 클릭 차단막이 남지 않아야 함). static은 딤이 있지만 클릭해도 닫히지 않음. 단 Esc는 열려 있음.

03

드래그 보호

확인: 팝업 안의 긴 문단에서 텍스트를 드래그하다가 딤 영역에서 마우스를 떼도 닫히지 않아야 합니다. click 하나만 보는 구현은 이때 닫혀서 작성 중이던 내용이 날아갑니다. 입력칸에 글자를 넣고 드래그로 선택한 뒤 딤에서 손을 떼보세요.

04

transform 조상 함정

아래 점선 상자는 transform·overflow:hidden·filter가 모두 걸려 있고, 팝업 마크업이 그 안에 작성되어 있습니다. 확인: 팝업이 상자 안에 갇히거나 잘리지 않고 화면 전체를 덮는지. 매니저가 열 때 <body> 끝으로 옮기기 때문에 정상 동작해야 합니다.

transform: translateZ(0) · overflow: hidden · filter

함정을 벗어난 팝업

이 팝업의 마크업은 transform이 걸린 상자 안에 있습니다. 그대로 두면 position: fixed가 그 상자를 기준으로 동작해 화면을 덮지 못하고, overflow: hidden에 잘립니다.

매니저는 열 때 원래 자리에 주석을 남기고 요소를 <body> 끝으로 옮기며, 닫을 때 제자리로 되돌립니다. 덕분에 작성 위치는 자유롭고 렌더링은 항상 정상입니다.

05

중첩 (2차 팝업)

확인: 1차 팝업 안에서 2차를 열면 2차가 위에 쌓이고, Esc를 한 번 누르면 2차만 닫히고 1차는 남아야 합니다. 2차가 열려 있을 때 1차의 버튼은 inert로 눌리지 않아야 하고, 둘 다 닫은 뒤에만 배경 스크롤이 풀려야 합니다.

06

배경 스크롤 잠금 · 위치 보존

확인: 팝업이 열린 동안 배경이 스크롤되지 않고, 닫은 뒤 원래 보던 위치로 정확히 돌아와야 합니다. 맨 위로 튀면 스크롤 위치 저장·복원이 빠진 것입니다. PC에서는 스크롤바가 사라질 때 레이아웃이 좌우로 흔들리지 않아야 합니다. iOS Safari 실기기 확인이 필수입니다.

07

키보드: Tab 순환 · 포커스 복귀

확인: 열면 첫 입력칸에 포커스가 가고, Tab을 계속 누르면 팝업 안에서만 순환(배경으로 빠져나가지 않음), Shift+Tab도 역순으로 순환. 닫으면 원래 눌렀던 버튼으로 포커스가 돌아와야 합니다. 마우스를 쓰지 않고 키보드만으로 열고 닫아보세요.

08

반복 개폐 · 결과 전달

확인: 같은 팝업을 5회 이상 열고 닫아도 정상 동작하고, 아래 로그에 열림/닫힘이 각각 1건씩만 기록되어야 합니다(중복되면 이벤트가 누적되는 것). 확인/취소를 누르면 결과가 로그에 함께 남습니다.
빠른 재개폐는 닫힘 트랜지션(200ms)이 끝나기 전에 같은 팝업을 다시 여는 경쟁 상황을 재현합니다. 뒤늦게 도착하는 닫기 마무리 콜백이 방금 열린 팝업을 숨겨버리면 안 되고, 닫은 뒤에는 원래 작성 위치로 정확히 복귀해야 합니다.

09

늦게 주입되는 트리거 (인클루드 상황)

아래 버튼은 페이지 로드 1초 후에 JS로 삽입됩니다. GNB/LNB가 인클루드로 나중에 들어오는 상황을 재현한 것입니다. 확인: 별도 바인딩 없이 그냥 동작해야 합니다 (document 위임이므로).

10

전체화면 · 클릭 위치 · 모바일 바텀시트

확인: 전체화면은 뷰포트를 꽉 덮고 닫으면 뒤 페이지 상태가 그대로 남아야 합니다 (주소창 때문에 아래가 잘리지 않는지 모바일에서 확인). 클릭 위치는 누른 버튼 쪽에서 자라나야 합니다. 화면 좌우 끝의 두 버튼을 각각 눌러 차이를 보세요. 바텀시트는 폭 640px 이하에서 아래에서 올라오는 형태로 바뀝니다.

이벤트 로그 0

기본 레이어팝업

가장 기본 형태입니다. 마크업은 페이지 안에 hidden 상태로 들어 있고, 버튼의 data-pop-open="basic"이 이 영역의 data-pop="basic"을 찾아 엽니다.

딤 클릭, Esc, 닫기 버튼, 우상단 X 모두 닫힙니다.

딤 true

딤이 깔리고, 딤을 클릭하면 닫힙니다. 기본값입니다.

딤 false

딤이 생성되지 않습니다. 레이어가 투명한 클릭 차단막으로 남지 않도록 pointer-events를 통과시키므로 뒤 페이지를 그대로 쓸 수 있습니다. 이 팝업은 data-pop-scroll="false"라서 배경 스크롤도 잠그지 않습니다.

딤 static

딤은 있지만 클릭해도 닫히지 않습니다. 필수 동의처럼 사용자가 반드시 선택해야 하는 팝업에 씁니다. Esc는 열어두었습니다 (data-pop-esc="false"로 막을 수 있습니다).

드래그 보호 테스트

아래 문단도 드래그해보세요. 마우스 버튼을 누른 지점이 패널 안이면, 손을 떼는 지점이 딤이어도 팝업이 닫히지 않습니다. pointerdown과 pointerup을 모두 확인하기 때문입니다.

반대로 딤에서 누르고 딤에서 떼면 정상적으로 닫힙니다. 눌러서 끌어 선택하는 동작과 닫으려는 의도를 구분하는 것이 핵심입니다.

1차 팝업

여기서 2차 팝업을 열면 위에 쌓입니다. 2차가 열린 동안 이 버튼들은 inert가 걸려 눌리지 않습니다.

2차 팝업 (재확인)

Esc를 누르면 이것만 닫히고 1차는 남습니다. 배경 스크롤은 1차까지 모두 닫힌 뒤에 풀립니다.

배송 정보 입력

주문을 취소할까요?

취소하면 되돌릴 수 없습니다. 선택 결과가 아래 로그에 기록됩니다.

늦게 들어온 버튼이 열었습니다

이 팝업을 연 버튼은 페이지 로드 후에 JS로 삽입된 것입니다. document에 위임해 두었기 때문에 추가 바인딩 없이 동작합니다. 인클루드로 들어오는 GNB/LNB의 버튼도 마찬가지입니다.

누른 곳에서 자라났습니다

트리거의 화면 좌표를 패널 기준 transform-origin으로 환산합니다. 절대좌표로 띄우지 않으므로 좁은 화면에서도 패널이 화면 밖으로 밀리지 않습니다.

전체화면 레이어

뷰포트를 덮지만 이동이 아니라 레이어입니다. 호스트 페이지가 뒤에 그대로 남아 있어 닫으면 즉시 복귀하고, 입력 중이던 폼 상태도 보존됩니다.

높이는 100dvh를 쓰므로 모바일 주소창이 나타나거나 사라져도 아래가 잘리지 않습니다. 노치·홈 인디케이터는 env(safe-area-inset-*)로 피합니다.

이동이 필요한 "독립페이지"는 매니저를 쓰지 않고 그냥 링크입니다. 북마크·공유·네이티브 웹뷰 대상일 때 그렇게 씁니다.

필터

창 폭을 640px 이하로 줄이면 아래에서 올라오는 시트로 바뀝니다. 그보다 넓으면 일반 중앙 팝업입니다. 같은 마크업으로 PC와 모바일을 모두 처리합니다.
