Button

사용자가 화면에서 어떤 동작을 “실행”하게 만드는 가장 기본적인 조각입니다. 이 문서의 모든 예시는 별도 스타일 없이 운영 중인 components.css의 클래스를 그대로 사용합니다 — 여기 보이는 모습이 곧 실제 화면의 모습입니다.

01

개요

버튼은 “지금 이 자리에서 무언가가 일어난다”는 신호입니다. 다른 페이지로 이동하는 것이 목적이라면 버튼이 아니라 링크(<a>)를 씁니다. 생김새 때문에 태그를 고르지 말고, 동작의 성격으로 고른 뒤 필요하면 클래스를 입혀주세요.

한 화면에 위계 세우기 .btn-row

주 동작 하나(Primary)를 정하고 나머지는 낮춥니다. 강조가 둘 이상이면 사용자는 무엇을 눌러야 할지 다시 읽게 됩니다. 

<div class="btn-row">
	<button class="btn btn--primary">변경사항 저장</button>
	<button class="btn">미리보기</button>
	<button class="btn btn--ghost">취소</button>
</div>
라벨은 동사로. “확인 / 예 / 제출” 대신 사용자가 얻는 결과를 씁니다 — 저장, 3건 배포, 초대 보내기. 버튼만 읽어도 무슨 일이 벌어질지 알 수 있어야 합니다.
02

해부

버튼 하나를 구성하는 요소와, 각 요소가 어떤 토큰에서 값을 가져오는지 보여줍니다. 아래 버튼은 그림이 아니라 실제 .btn.btn--primary.btn--lg 요소입니다.

  1. 1 컨테이너 — 높이는 크기 토큰(--btn-h-lg 44px)이 정하고, 좌우 여백만 --sp-24로 늘어납니다. 세로 패딩은 쓰지 않습니다.
  2. 2 아이콘 슬롯 — 선택 요소. 텍스트 버튼 안에서는 16px(큰 버튼 18px), 라벨과의 간격은 --sp-8로 고정됩니다.
  3. 3 라벨 — 13px / 600. 줄바꿈하지 않으며(white-space: nowrap) 길어지면 버튼이 늘어납니다.
  4. 4 모서리 — --radius-md 10px. 작은 버튼만 --radius-sm 6px으로 낮춰 비율을 맞춥니다.
03

스타일 변형

다섯 가지는 “예쁨의 종류”가 아니라 강조의 단계입니다. 위에서 아래로 갈수록 시선을 덜 끕니다. 한 화면에서 Primary는 하나, Danger는 되돌릴 수 없는 동작에만 씁니다.

강조 단계 .btn--primary / .btn / .btn--subtle / .btn--ghost / .btn--danger
주 동작 · 화면당 1개 보조 동작 강조하되 가볍게 밀집 UI · 취소 파괴적 동작 
<button class="btn btn--primary">Primary</button>
<button class="btn">Default</button>
<button class="btn btn--subtle">Subtle</button>
<button class="btn btn--ghost">Ghost</button>
<button class="btn btn--danger">Danger</button>
Danger는 “빨간 Primary”가 아닙니다. 삭제·초기화처럼 되돌릴 수 없는 동작에만 쓰고, 그 동작이 실행되기 전에 반드시 확인 단계를 둡니다. 자주 쓰는 저장 버튼을 눈에 띄게 하려고 빨강을 쓰면 정작 위험한 순간에 경고가 작동하지 않습니다.
04

크기

높이만 바뀌는 게 아니라 좌우 여백·글자 크기·모서리까지 함께 움직입니다. 한 영역 안에서는 한 가지 크기로 통일하세요.

세 단계 .btn--sm / (기본) / .btn--lg
28px · 표 안, 밀집 영역 36px · 기본값 44px · 히어로, 모바일 
<button class="btn btn--primary btn--sm">Small</button>
<button class="btn btn--primary">Medium</button>
<button class="btn btn--primary btn--lg">Large</button>
크기 높이 토큰 좌우 여백 글자 모서리 아이콘
.btn--sm --btn-h-sm 28px --sp-12 12px 12px / 600 --radius-sm 14px
.btn 기본 --btn-h-md 36px --sp-16 16px 13px / 600 --radius-md 16px
.btn--lg --btn-h-lg 44px --sp-24 24px 14px / 600 --radius-md 18px
05

상태

마우스를 올리거나 키보드로 이동해야만 보이는 상태는 캡처하기 어렵습니다. 아래 스위치를 누르면 .is-hover 같은 미러 클래스로 상태를 고정해 볼 수 있습니다 — 실제 의사 클래스와 같은 스타일을 공유하므로, VRT 스냅샷을 찍을 때도 그대로 쓸 수 있습니다.

아래 예시 버튼에 즉시 반영됩니다
상태 미리보기 :hover / :focus-visible / :active / :disabled 
<!-- 실제 코드에서는 의사 클래스가 알아서 동작합니다 -->
<button class="btn btn--primary">Primary</button>

<!-- 스냅샷·가이드에서 상태를 고정해야 할 때만 미러 클래스 사용 -->
<button class="btn btn--primary is-hover">Primary</button>
<button class="btn btn--primary is-focus">Primary</button>
비활성 · 로딩 [disabled] / .is-loading + .btn__spinner

로딩 중에는 라벨을 지우지 말고 진행 중임을 말해주는 라벨로 바꿉니다. 버튼 너비가 갑자기 줄면 옆 버튼이 밀립니다.

disabled .is-loading disabled · default 
<button class="btn btn--primary" disabled>저장</button>

<button class="btn btn--primary is-loading" aria-busy="true">
	<span class="btn__spinner" aria-hidden="true"></span>
	저장 중…
</button>
06

아이콘 조합

아이콘은 라벨을 보조할 뿐 대체하지 않습니다. 앞에 붙이면 동작의 종류를, 뒤에 붙이면 이동·펼침 같은 방향을 뜻합니다.

앞 · 뒤 · 아이콘 전용 .btn > svg / .btn--icon
앞 아이콘 · 동작의 종류 뒤 아이콘 · 이동 아이콘 전용 · aria-label 필수 
<button class="btn btn--primary">
	<svg viewBox="0 0 24 24" ...></svg>
	승인
</button>

<button class="btn">
	상세 보기
	<svg viewBox="0 0 24 24" ...></svg>
</button>

<!-- 아이콘만 있을 때는 이름을 반드시 따로 준다 -->
<button class="btn btn--icon" aria-label="삭제">
	<svg viewBox="0 0 24 24" ...></svg>
</button>
07

그룹 · 정렬

버튼을 나란히 둘 때 간격은 --sp-8로 고정하고, 정렬은 맥락이 정합니다. 폼과 모달은 오른쪽 정렬, 툴바는 왼쪽 정렬이 기본입니다.

정렬 .btn-row--end / --center / --between

오른쪽 정렬에서는 주 동작을 가장 오른쪽에 둡니다 — 시선과 커서가 마지막에 닿는 자리입니다. 

<!-- 툴바 : 왼쪽 -->
<div class="btn-row">…</div>

<!-- 폼 · 모달 : 오른쪽, 주 동작이 맨 끝 -->
<div class="btn-row btn-row--end">
	<button class="btn btn--ghost">취소</button>
	<button class="btn btn--primary">저장</button>
</div>

<!-- 단계 이동 : 양끝 -->
<div class="btn-row btn-row--between">…</div>
세그먼트 그룹 .btn-group

서로 배타적인 선택지일 때만 씁니다. 성격이 다른 동작을 붙여 놓으면 하나의 덩어리로 오해합니다. 

<div class="btn-group" role="group" aria-label="보기 방식">
	<button class="btn is-selected" aria-pressed="true">전체</button>
	<button class="btn" aria-pressed="false">대기</button>
	<button class="btn" aria-pressed="false">완료</button>
</div>
전체 너비 .btn--block

모바일 하단 고정 영역이나 좁은 카드 안에서만 씁니다. 넓은 화면에서 늘리면 라벨과 테두리 사이가 비어 어색해집니다.

<button class="btn btn--primary btn--lg btn--block">계속하기</button>

09

접근성

퍼블리싱 단계에서 지켜지지 않으면 나중에 고치기 가장 비싼 항목들입니다. 리뷰 전 아래를 확인해주세요.

  • 동작은 <button>, 이동은 <a>. <div>에 클릭 이벤트만 얹으면 키보드로 도달할 수 없고 스크린 리더가 버튼으로 읽지 않습니다.
  • 아이콘 전용 버튼에는 aria-label. 시각적 라벨이 없으면 이름도 없는 버튼이 됩니다.
  • 포커스 링을 지우지 마세요. outline: none만 남기면 Tab 사용자가 현재 위치를 잃습니다. 이 시스템은 :focus-visible로 마우스 클릭 때만 숨깁니다.
  • 토글 상태는 aria-pressed로 알립니다. 세그먼트 그룹에서 색만 바꾸면 보이지 않는 사용자에겐 아무 일도 일어나지 않은 것과 같습니다.
  • 터치 영역은 최소 44×44. 작은 버튼(28px)을 모바일에서 쓸 땐 주변 여백까지 포함해 손가락이 닿을 넓이를 확보하세요.
  • 로딩 중에는 aria-busy="true". 스피너는 aria-hidden으로 감추고, 상태는 라벨 텍스트로 전달합니다.
10

사용 규칙

실제 리뷰에서 가장 자주 되돌아오는 두 가지입니다.

권장

주 동작 하나만 강조하고, 라벨에 대상과 개수를 담았습니다. 누르기 전에 무슨 일이 벌어질지 알 수 있습니다.

지양

강조가 셋이라 눈이 갈 곳을 못 찾고, 라벨만 봐서는 무엇이 실행되는지 알 수 없습니다. Danger를 강조 용도로 쓴 것도 문제입니다.

권장

한 줄 안에서는 크기를 통일했습니다. 위험한 동작은 강조를 낮춰 실수로 누르기 어렵게 두었습니다.

지양

크기가 제각각이라 정렬선이 무너지고, 가장 위험한 삭제가 가장 눈에 띄어 오조작을 부릅니다.
